# VibeZone API for native apps

Contract: [`openapi/vibezone-api.json`](../../openapi/vibezone-api.json) (regenerated by `dotnet build`).
Postman: import [`VibeZone.postman_collection.json`](VibeZone.postman_collection.json); its description
has a quick start. Design: [ADR-0007](../adr/0007-native-app-token-auth.md) (tokens),
[ADR-0008](../adr/0008-response-envelope-and-playback-urls.md) (response format, playback URLs).

The collection is generated by `node scripts/generate-postman-collection.cjs`; when endpoints change,
update the script together with the OpenAPI contract and regenerate.

## Base URL (local Docker stack)

Ports bind to `127.0.0.1` only, so the app must reach the PC's loopback:

| Where the app runs | Base URL |
|---|---|
| Android emulator | `http://10.0.2.2:3000` |
| Android phone over USB | `adb reverse tcp:3000 tcp:3000`, then `http://localhost:3000` |
| iOS simulator | `http://localhost:3000` |
| Physical iPhone / Wi-Fi device | not supported by the local stack (would need LAN binding + TLS); use a staging server |

Local is plain HTTP: allow cleartext **in debug builds only** (Android `usesCleartextTraffic` /
`network_security_config` for `10.0.2.2`/`localhost`; iOS `NSAppTransportSecurity` →
`NSAllowsLocalNetworking`). Production is HTTPS only.

## Response format

Every successful JSON response is an envelope. Errors are not:

| Response | Body |
|---|---|
| One object (2xx) | `{ "data": { … } }` |
| List (2xx) | `{ "data": [ … ], "meta": { "page": 1, "pageSize": 20, "total": 57, "hasMore": true } }` |
| No content | `204`, empty body |
| Error (4xx/5xx) | RFC 9457 Problem Details, `application/problem+json` (see [Errors](#errors)), with **no** `data` key |

Check the HTTP status first, then read `data` on success or `code` on error.

Paged lists (`GET /tracks`, `GET /me/tracks`) take `?page=1&pageSize=20` (max 50). Keep loading the
next page while `meta.hasMore` is true. Small complete lists (genres, sessions) come back as a single page.

```dart
T unwrap<T>(Response r, T Function(Map<String, dynamic>) fromJson) =>
    fromJson(r.data['data'] as Map<String, dynamic>);

class Page<T> {
  Page(this.items, this.page, this.pageSize, this.total, this.hasMore);
  final List<T> items;
  final int page, pageSize, total;
  final bool hasMore;

  factory Page.fromResponse(Response r, T Function(Map<String, dynamic>) fromJson) {
    final meta = r.data['meta'] as Map<String, dynamic>;
    return Page(
      (r.data['data'] as List).map((e) => fromJson(e as Map<String, dynamic>)).toList(),
      meta['page'] as int, meta['pageSize'] as int, meta['total'] as int, meta['hasMore'] as bool,
    );
  }
}
```

## Authentication

1. `POST /api/v1/auth/register` → 202; the user confirms the email.
   - The link points at the web app (`/{locale}/verify-email?userId=…&token=…`).
   - Until deep links exist, confirm in the browser, or have the app call
     `POST /api/v1/auth/verify-email {userId, token}` with the link's values.
2. `POST /api/v1/auth/token {email, password, deviceName}` →
   `{data: {accessToken, tokenType: "Bearer", expiresIn: 900, refreshToken, refreshTokenExpiresAt}}`.
3. Send `Authorization: Bearer <accessToken>` on every request. No cookies, no CSRF token.
4. On `401` from any API call:
   - Refresh **once** (`POST /api/v1/auth/token/refresh {refreshToken}`), store the new pair and retry the request.
   - If the refresh returns `401 invalid_refresh_token`, go to the login screen.
5. Sign out: `POST /api/v1/auth/token/revoke {refreshToken}`, then delete both tokens.

Rules:

- Refresh tokens are **single use**.
  - Run at most one refresh at a time and queue other requests behind it.
  - Sending a refresh token that was already used signs the device out.
- Keep the refresh token in `flutter_secure_storage`; the access token can stay in memory. Never log
  either of them.
- Sessions last 30 days from sign-in; after that the user signs in again. The app session also ends when:
  - the password is changed or reset on any device;
  - the user chooses "sign out" for this device in the web app's device list.

Minimal `dio` interceptor (single-flight refresh):

```dart
class AuthInterceptor extends QueuedInterceptor {
  AuthInterceptor(this.dio, this.store);
  final Dio dio;
  final TokenStore store; // secure storage wrapper

  @override
  void onRequest(RequestOptions o, RequestInterceptorHandler h) async {
    final token = await store.accessToken();
    if (token != null) o.headers['Authorization'] = 'Bearer $token';
    h.next(o);
  }

  @override
  void onError(DioException e, ErrorInterceptorHandler h) async {
    final retried = e.requestOptions.extra['retried'] == true;
    if (e.response?.statusCode != 401 || retried) return h.next(e);
    final refresh = await store.refreshToken();
    if (refresh == null) return h.next(e);
    try {
      // QueuedInterceptor runs onError calls one at a time, so only one refresh is in flight.
      final r = await Dio(BaseOptions(baseUrl: dio.options.baseUrl))
          .post('/api/v1/auth/token/refresh', data: {'refreshToken': refresh});
      final t = r.data['data'];
      await store.save(t['accessToken'], t['refreshToken']);
      final o = e.requestOptions..extra['retried'] = true;
      o.headers['Authorization'] = 'Bearer ${t['accessToken']}';
      h.resolve(await dio.fetch(o));
    } on DioException {
      await store.clear(); // → navigate to login
      h.next(e);
    }
  }
}
```

A request that waited in the queue while another one refreshed should not refresh again. Before
refreshing, compare the stored token with the token that request was sent with; if they differ,
just retry with the stored token.

## Errors

RFC 9457 Problem Details, for example
`{"status": 400, "code": "handle_invalid", "errors": {"handle": ["handle_invalid"]}, "traceId": "…", …}`.

- Map `code` to your own localized text; don't show `title`.
- Include `traceId` in bug reports.
- `429` means rate limited (auth endpoints: 10/min per IP).

## Media

Upload a new track (one request, all or nothing):

- `POST /api/v1/track-uploads` as `multipart/form-data`: `title`, `visibility` (`Public` | `Unlisted` |
  `Private`), optional `genreSlug` and `description`, optional `artwork` file, and the `audio` file last.
- `202` → `data` is the upload status, `Location: /api/v1/tracks/{id}`. On any `400` no track was created;
  `errors` names the field (`title`, `audio`, `artwork`, …).
- Cover: JPEG, PNG or WebP, at least 200 × 200 px, up to 10 MB. It is cropped to a square and re-encoded
  (metadata removed). Tracks expose `artwork: {small, large} | null` — relative URLs that change when the
  cover changes, so they can be cached. `PUT /api/v1/tracks/{id}/artwork` (raw image body) replaces it,
  `DELETE` removes it.

Albums, search and playlists (ADR-0010):

- Albums: `POST /albums`, `GET|PATCH|DELETE /albums/{id}`, `PUT /albums/{id}/tracks` (complete tracklist in
  order), `GET /me/albums`. `TrackDto.album` / `trackNumber` link a track to its album; `ArtistProfileDto.albums`.
- Search: `GET /search?q=` (6 of each kind + totals), `GET /search/{tracks|artists|albums}?q=&page=` (paged),
  `GET /playlists?q=` for public playlists. Accents optional.
- Playlists: `POST /playlists`, `GET|PATCH|DELETE /playlists/{id}`, `GET /playlists/{id}/tracks`,
  `POST /playlists/{id}/tracks` `{trackId}`, `DELETE /playlists/{id}/tracks/{trackId}`,
  `PUT /playlists/{id}/tracks/order` `{trackIds}`, `GET /me/playlists?containsTrack=`.

Artist images (signed-in artist): `PUT /api/v1/me/artist/avatar` (square, ≥ 200 × 200) or
`/banner` (3:1, ≥ 600 × 200) with the image as the raw body; `DELETE` the same path removes it.
`ArtistDto.avatar` / `banner` = `{small, large} | null`; track lists carry `artist.avatarUrl`.

Upload audio for an existing track (a Draft, or again after `Failed`/`Cancelled`):

- `PUT /api/v1/tracks/{id}/upload` with the file as the **raw body** (not multipart).
- Headers: `Content-Type: application/octet-stream`, `X-Upload-Length: <exact bytes>`, and optionally
  `X-File-Name: <url-encoded>`.
- Limits: 200 MB, 1 s–2 h of audio.
- `202` → `data` is the upload status. Then poll `GET /api/v1/tracks/{id}` every 2–5 s until `status`
  is `Ready` or `Failed`; on failure, `processingError` holds the code.

### Playback (just_audio)

Get a playback URL first, then give the player a plain URL with no headers and no cookies. This
works with background playback (`just_audio_background` / `audio_service`), on iOS, and for long
tracks, because the 15-minute access token is not involved.

1. Call `GET /api/v1/tracks/{id}/playback`, with the bearer token if signed in. It returns
   `{data: {trackId, streamUrl, waveformUrl, contentType: "audio/mp4", sizeBytes, durationMs, expiresAt}}`.
   - Public tracks: anonymous listeners can call it too.
   - Private tracks: only the owner can; anyone else gets `404`.
   - `streamUrl` and `waveformUrl` are **relative** to the base URL and include `?token=…`.
   - They work until `expiresAt` (about 6 hours). Don't store them across app restarts.
2. Play `baseUrl + streamUrl`. It is AAC in MP4 with HTTP Range support, so seeking downloads only
   the bytes it needs.
3. If the source fails, call `/playback` again and resume at the same position. Typical causes:
   - The link expired: the stream answers `401 playback_token_invalid`.
   - The access was lost: if `/playback` itself answers `404`, the track was made private or deleted,
     or it isn't ready. Stop and show an error.

```dart
Future<void> playTrack(AudioPlayer player, String trackId, {Duration start = Duration.zero}) async {
  final r = await dio.get('/api/v1/tracks/$trackId/playback');
  final p = r.data['data'];
  final uri = Uri.parse(dio.options.baseUrl).resolve(p['streamUrl'] as String);
  await player.setAudioSource(
    AudioSource.uri(uri, tag: MediaItem(id: trackId, title: '…')), // tag: just_audio_background
    initialPosition: start,
  );
  await player.play();
}

// e.g. resumed after hours on pause: the old link has expired, so fetch a new one and continue.
player.playbackEventStream.listen((_) {}, onError: (Object e, StackTrace _) async {
  if (e is PlayerException) {
    await playTrack(player, currentTrackId, start: player.position);
  }
});
```

Waveform peaks: `GET baseUrl + waveformUrl` →
`{data: {version, durationMs, peaks: [up to 1000 values in 0..1]}}`.

Credentials also work in place of the token: the web app calls `GET /tracks/{id}/stream` with its
cookie, and a bearer token works the same way. In the app, prefer `/playback`.
