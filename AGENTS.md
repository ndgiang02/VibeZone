## 4. Architecture rules

1. Modular monolith. No microservices, Kafka, Kubernetes, OpenSearch or HLS until the plan's
   milestone (M6) and a measured need.
2. Inside a module: `Endpoints → Application → Domain`; `Infrastructure` implements
   `Application` ports. `Domain` has no framework/database/storage dependencies.
3. Modules interact only via `*.Contracts` (interfaces, DTOs, versioned integration events).
   Never reference another module's entities, DbSets or tables.
4. One `AppDbContext`, schema per module, snake_case, UUIDv7 keys, `timestamptz` UTC.
5. Business rules (visibility, ownership, valid listen, track state machine) live in
   Domain/Application, not in endpoints or React components.
6. Background work goes through the Postgres job queue / outbox (ADR-0004).
7. Frontend: exactly **one** audio engine (global player store + single media element). Track
   cards dispatch actions; they never create `Audio` objects or their own wavesurfer media.
8. Add a dependency only when it is used now, is maintained, and its licence is compatible.
   Pin versions (lockfiles, exact image tags).

## 5. Security rules

- Enforce authorization on the server for every endpoint; resource-based checks for ownership.
  Invisible resources return 404.
- Never commit secrets. `.env` is ignored; `.env.example` contains placeholders only.
- Never log passwords, tokens, cookies, reset/verification links, signed URLs, full IPs.
- Auth = Identity + HttpOnly `__Host-` cookie + server-side sessions + antiforgery (ADR-0002).
  No tokens in localStorage/sessionStorage.
- Never trust client filename/MIME; validate media with `ffprobe` server-side.
- Never build shell commands from input. Use `ProcessStartInfo.ArgumentList`.
- Storage is private by default; object keys are server-generated.
- User-generated text is stored as plain text and rendered escaped.
- New trust boundary or data class ⇒ update `docs/architecture/security.md`.

## 6. Coding conventions

**C#**: nullable enabled, warnings as errors, file-scoped namespaces, `sealed` by default,
records for DTOs/value objects, `CancellationToken` on every async I/O path, `TimeProvider` for
time, no `async void`, no static mutable state. Minimal APIs grouped per module
(`MapGroup("/api/v1/...")`). Validation at the edge (request DTO) and invariants in Domain.
Errors returned as RFC 9457 Problem Details. Central package management
(`Directory.Packages.props`).

**TypeScript**: `strict: true`, no `any` (use `unknown` + Zod), ESLint + Prettier clean,
Server Components by default, `"use client"` only where needed. API types generated from
OpenAPI. Components: PascalCase files; hooks `useX`; Zustand stores in `src/stores`.

**UI**: dark-first design tokens (charcoal background, coral-orange accent) defined once as CSS
variables/Tailwind theme; every data view has loading, empty, error and success states;
keyboard accessible, visible focus, ARIA on player controls; no autoplay before user gesture.

**Naming**: REST paths plural nouns, kebab-case; JSON camelCase; DB snake_case.

**i18n (vi default, en)**: every user-visible string lives in `apps/web/messages/{vi,en}.json` — never
hardcode UI text. Keys are type-checked; a unit test enforces identical keys and placeholders in both
files. Navigation uses `@/i18n/navigation` (`Link`, `useRouter`, `usePathname`), not `next/link` /
`next/navigation`. Email templates are localized server-side from the user's profile locale.

**API errors**: endpoints return Problem Details with a stable snake_case `code` (and
`errors[field] = [code]` for field validation). Add every new code to `messages/*/errors`; the web
app maps codes → text (`errorCode()`, `applyServerErrors()`), never rendering server titles.

**shadcn/ui**: add components with `npm run ui:add -- <name>` (rewrites the registry's `cn` import to
`@/lib/utils`; do not depend on the `cn` package).

**Auth in the web app**: the API client adds `X-CSRF-TOKEN` to unsafe requests and retries once on
`csrf_invalid`. Pages needing a user call `useRequireUser()` (UX only; the API authorizes). Pages are
rendered per request for the CSP nonce (ADR-0006) — do not re-enable `cacheComponents`.

**Mock data**: allowed only in tests, Storybook-style previews, or dev seed commands that are
clearly labelled. Never to fake a feature in the running app.

## 7. Testing & verification workflow

For every change:

1. Build: `dotnet build -warnaserror`, `npm run typecheck && npm run lint` (once projects exist).
2. Run the relevant tests (unit → integration with Testcontainers → e2e with Playwright).
3. For infrastructure changes: `bash scripts/verify-local-infra.sh`.
4. Report the **actual** command output. A step not run is reported as not run. A failing test is
   never skipped, deleted or weakened to make CI green without explicit agreement.

Integration tests run against real PostgreSQL and Mailpit containers (Testcontainers) and create
users through the public API (`TestUsers`), reading confirmation/reset links from Mailpit. E2E
(Playwright) does the same in a browser and fails on any CSP violation; it runs with 3 workers
locally (8 GB machine) and needs the Compose `app` profile stopped (port 5080).

Test expectations: authorization tests for each protected resource (including cross-user IDOR),
Range-request tests for streaming, upload accept/reject tests with real media fixtures,
architecture tests for layering rules.

## 8. Definition of Done (feature)

Implemented end-to-end (UI ↔ API ↔ DB where applicable) · server-side authorization ·
loading/empty/error states · tests written **and run** · build green · migration added if the
schema changed · docs updated (data-model, security, plan) · limitations recorded in
`docs/progress.md`.

## 9. Process

- Work one milestone at a time (IMPLEMENTATION_PLAN.md). Do not start the next milestone until the
  current one meets its acceptance criteria and has been reported.
- At the end of a work session: update task checkboxes, append a dated entry to
  `docs/progress.md` (what was done, what was verified and how, known issues, next steps).
- Ask the project owner before: architectural changes not covered by an ADR, adding
  infrastructure, destructive data operations, anything touching production, commits/pushes
  unless asked.
- Never delete user data or overwrite uncommitted user changes.

## 10. Common commands

```bash
cp .env.example .env                      # then fill secrets (see comments in the file)
docker compose up -d --wait               # postgres only
docker compose --profile media up -d --wait   # + MinIO (M3)
docker compose --profile "*" up -d --wait     # all local dependencies
bash scripts/verify-local-infra.sh        # verify running dependencies
docker compose --profile "*" down         # stop (keeps volumes)
docker compose --profile "*" down -v      # stop and DELETE local data

# Backend
bash scripts/setup-dev-secrets.sh         # .env -> user-secrets (connection string)
bash scripts/db-migrate.sh                # apply migrations
dotnet ef migrations add <Name> --project src/VibeZone.Migrations --startup-project src/VibeZone.Migrations --output-dir Migrations
dotnet build VibeZone.slnx -warnaserror   # also regenerates openapi/vibezone-api.json
dotnet test --solution VibeZone.slnx
dotnet format VibeZone.slnx --verify-no-changes
dotnet run --project src/VibeZone.Api     # http://localhost:5080

# Frontend (apps/web, Node 24)
npm run dev | lint | typecheck | format:check | test | build
npm run api:generate                      # after any API contract change
npx playwright test                       # after `npm run build`; starts API + web itself
```

Reference data (e.g. genres) that every environment needs is seeded via EF `HasData` in a
migration. Demo/sample content is never put in migrations.
